# 同会话原始里程闭环返程

当前公开版本对应维护者报告已完成实车返回测试的“单击启动”版本。它记录去程实际驱动里程与车身朝向，返程以当前位置闭环追踪，不重放去程速度/舵机时间序列。地图用于去程导航，地图位置差不是返程主要门槛。

## 数据和控制约束

驱动 `/odom` 的真实 frame 是 `odom_combined`、child 是 `base_footprint`；这是驱动积分的原始数据，与 EKF/TF 的同名坐标不能混用。native relay 以每条消息实际 DDS GID、relay实例、序号封装反馈；面板和仲裁分别验证来源、时序、连续性、有限值、跳变。记录与候选绑定driver/relay/面板/仲裁会话，重启和重置不能套用旧轨迹。

累计位移与展开航向检查路线几何，避免低速瞬时角速度比值不稳定导致错误地把单帧当作整条路线不可返程。拒绝时保存首个样本及具体原因，不修改或平滑实际记录。

现场验收使用目标0.15m/s、反馈停车阈值0.4m/s、记录路线最大4m，另保留90秒及路线长度相关失控保护。反馈阈值允许较大的原始速度偏差，不代表地面速度已标定或目标速度能准确跟随。公开配置仍为disabled，不能将现场授权或验收结论直接移植到另一台设备。

完整试验策略为supervised_trial，需要明确现场授权；第一次非零发布之前原子持久化消耗一次许可，复位、重启、恢复通信和重复准备不能使旧许可重新可用。正式supervised_route的验收回执要求独立保留。默认不附带任何现场许可。

准备完成后，显式单击创建唯一运行会话；鼠标松开不会取消，重复点击不能重启任务。GUI每50ms推进运行序号，独立仲裁要求250ms内持续推进；ROS线程继续发送同一旧序号不能维持运动。点击停止、红色软件停车、应用失活/隐藏/关闭、GUI或授权失联、原始来源异常、冻结/跳变、偏差、无进展、竞争控制或到点均停止，不自动恢复。单调时钟在取得共享锁后采样，避免GUI先更新造成负年龄误停；没有放宽新鲜度门槛。

解除停车需显式人工请求：驱动复位ACK → 同驱动会话的后续新鲜未锁状态 → 仲裁确认零速复位 → 面板匹配仲裁实例、拥有者和请求序号后显示解除。等待期间仍显示锁定，禁止重复请求；拒绝、超时、旧ACK、重启或急停均保持停车。静态控制图就绪与驱动运动就绪分开，启动锁不会造成无法请求复位的死锁。

启动时DDS发现尚未完成仍可触发停车，故障不会自动清除。现场最近一次单击返程正常完成，但启动阶段曾因驱动状态/原始反馈过期而再次锁定；两次显式解除都收到确认，后一次是新故障后的复位，不能据此宣称所有启动期重锁已消除。具体失败原因显示为graph_reason或状态新鲜度错误，不能反复解锁掩盖持续故障。

软件停车依赖软件/通信；物理急停直接断电和下位机断连停车是维护者的现场确认，不是本仓库自动化验收结论。驱动进程死亡、主机崩溃时下位机是否独立超时停车仍未确认。

原始里程是速度积分，没有独立地面位置或轮胎转角验证；路径记录无法发现返程时新出现的障碍，没有后向自动避障。日志中的里程不能直接称作实际地面位移或物理停距。

## 原始里程relay

C++ relay只订阅Odometry、发布包含来源身份的JSON消息；不发布速度、不打开串口。需要ROS 2 Humble的ament_cmake、rclcpp、nav_msgs、std_msgs以及CMake/C++17：

```bash
source /opt/ros/humble/setup.bash
cmake -S native -B build/raw-relay -DCMAKE_INSTALL_PREFIX="$PWD/raw-odom-tools"
cmake --build build/raw-relay
cmake --install build/raw-relay
```

二进制和构建产物由Git忽略，不随源码发布。

## 外部驱动契约

不分发厂家驱动源码或设备配置。真实接入必须提供经审核的gated driver前缀：`CHARGING_GATED_DRIVER_PREFIX`；启动器验证包解析来自该前缀，仲裁核验只读参数`charging_return_driver_gate_version=2`。驱动只能订阅`/charging_control/chassis`，命令队列KeepLast(1)，不能保留`/red_vel`、`/robot_recharge_flag`、`/set_charge`等旁路。

v2要求独立于ROS执行器和阻塞串口RX的20ms TX线程。命令/有效原始反馈间隔超过250ms、非法命令或发送失败会锁存并持续发送零帧；新消息或连接恢复不能清锁。驱动状态带启动UUID、递增序号与源单调时间；显式复位需新鲜零命令、连续静止反馈及近期发送成功。自有实现与完整集成契约见 [看门狗源码](../native/driver-watchdog/README.md)。仅加入头文件、保留旧串口writer不能形成唯一控制链。

独立TX也属于驱动进程，不能在整个进程或主机死亡后继续工作。成功写串口仅表示内核接收，不等于MCU执行确认；250ms是过期门槛，真实停车还受线程调度、发送和底盘制动影响。真实串口双句柄行为、MCU独立命令超时和地面停距必须另行核实。

`CHARGING_ROBOT_SETUP`指定现有ROS工作空间，`CHARGING_NAV2_PARAMS`指定经许可且已现场核验的导航参数。公开仓库不提供/启用物理驱动，不复制现场校准和导航YAML。缺少以上依赖时应拒绝硬件启动。

## 诊断与测试

诊断包含按钮时序、请求、仲裁实际软件发布v/w、接收时刻、原始反馈、来源/序号及停止原因。单调时钟适用于同主机同启动会话的进程比较；ROS时钟用于源年龄和跳变检查。软件发布不等于下位机执行确认，角速度命令不等于轮胎转角实测。

`tests/run_local.sh`执行纯逻辑、Qt和配置描述测试，不运行ROS控制节点。`tests/run_isolated.sh`只可在操作者已经建立的私有网络/PID/设备命名空间中运行；普通ROS_DOMAIN_ID不能替代隔离。仿真测试使用合成地图和轨迹。原始现场地图、轨迹、GID、许可、日志、备份和环境凭据不随仓库分发。
